# Лендинг и клиентское приложение на LOTIS

Лендинг остаётся одной публичной страницей. `index.php` собирает её через настоящие `LTS::Html` и `LTS::Space` из клонированного репозитория. Авторизация, создание заявок, хранение данных и проверка прав принадлежат отдельному клиентскому приложению и здесь не реализованы.

## Запуск

Из корня проекта на PHP-сервере откройте `/index.php`. Для локального просмотра:

```powershell
php -S 127.0.0.1:4173 -t .
```

На этой машине переносимый PHP для проверки сохранён в `qa/runtime/php/php.exe`:

```powershell
& .\qa\runtime\php\php.exe -S 127.0.0.1:4173 -t .
```

Для обычного статического размещения используйте `index.html` или `rocket.html`. PHP берёт из выбранного шаблона head/body, сохраняет метаданные и подключает те же стили, изображения и сценарии. jQuery из `external/jquery/jquery.js` нужен штатному сборщику `Space`; файл скопирован из `LOTIS/examples/external/jquery/`, с сохранённым заголовком лицензии. jQuery UI и клиентское ядро LOTIS на лендинге отключены, поскольку здесь нет событий приложения. `Space` автоматически подключает декларацию `Events.js`; адаптер исправляет жёстко заданные пути ресурсов `/newlotis/` на относительные `LOTIS/newlotis/`, не меняя фреймворк.

## Подключение настоящего кабинета

Верхний переключатель выбирает первую страницу (`index.php`) или вторую (`index.php?version=rocket`). В статическом режиме ссылки ведут на `index.html` / `rocket.html`. В PHP адаптере выбор ограничен этими двумя шаблонами; обе версии используют один `config.php`. На текущей машине повторная проверка PHP после добавления второй версии не выполнена: запуск переносимого PHP блокирует политика Windows. Статические страницы и их интерфейсы проверены в браузере.

В PHP-версии заполните `integration/lotis/config.php`:

```php
return [
    'routes' => [
        'login' => '/cabinet/index.php?page=login',
        'request' => '/cabinet/index.php?page=request-new',
        'partner' => '/cabinet/index.php?page=partner-request',
    ],
];
```

Это примеры будущих маршрутов: таких страниц в проекте сейчас нет. Укажите реальные адреса готового приложения. Для отдельного поддомена допустимы абсолютные HTTPS-адреса. Для размещения в подпапке укажите путь с её префиксом.

Для статического размещения те же три поля заполните в `site-config.js`. Не храните в этих файлах пароли, ключи или токены: настройки навигации публичны. PHP-конфигурация автоматически передаёт только этот публичный объект в браузер; в исходном коде лендинга правки больше не нужны.

| Действие | Атрибут | Поле routes | Поведение без маршрута |
| --- | --- | --- | --- |
| Вход | `data-app-action="login"` | `login` | Сообщение о подготовке кабинета и переход к его описанию |
| Новая заявка | `data-app-action="request"` | `request` | Подготовка локального брифа, без отправки данных |
| Обращение партнёра | `data-app-action="partner"` | `partner` | Локальный бриф складской площадки |

Каждый заполненный маршрут включается независимо. Ссылки входа получают настоящий `href`, поэтому работают в новой вкладке. Кнопки переводят пользователя в приложение в текущей вкладке. Скачивание брифа заменяется переходом автоматически.

После выбора направления услуги кнопка передаёт query-параметр `service`: `storage`, `handling` или `flexible`. Он только предварительно выбирает услугу. В приложении проверьте его по этому списку; неизвестное значение игнорируйте. Не используйте его как имя PHP-файла, таблицы или команды. Текущие параметры и hash настроенного URL сохраняются.

Вход и регистрация определяются приложением: если создание заявки требует авторизации, сохраните выбранную услугу на сервере, предложите вход и верните пользователя к форме. Лендинг не читает сессию кабинета, не определяет роль по localStorage и не переносит токены через URL.

## Содержание кабинета, показанное на странице

- Новая заявка: город, груз, объём, сроки, требования к хранению.
- История обращений компании.
- Статусы как согласованная концепция: `Новая` → `Подбор склада` → `Склад подобран` → `Завершена`.

Эти статусы иллюстрируют будущий процесс. При реализации сопоставьте их с реальными состояниями и переходами системы. Цифры, ООО «Меридиан», заявки и уведомление в превью — демонстрационные. Автоматический расчёт стоимости, онлайн-оплата, чат и учёт складских остатков не обещаются.

## Размещение

PHP требует обычный PHP-хостинг. Текущая публикация Sites статическая, она показывает `index.html` и не исполняет PHP. Адрес готового PHP-приложения можно подключить через `site-config.js`, сохранив лендинг на Sites, либо разместить весь комплект на PHP-хостинге.

Для PHP-размещения нужны `index.php`, `index.html`, `rocket.html`, `integration/lotis/config.php`, CSS/JS-файлы из корня, `assets/`, `external/jquery/` и `LOTIS/newlotis/`. Папки `.git`, `qa`, документация и примеры LOTIS в публичный корень не требуются. Не изменяйте исходники фреймворка ради лендинга. Настройте DirectoryIndex на `index.php` (или открывайте его явно); для статического режима используйте `index.html`.

Лендинг принимает только GET/HEAD. POST получает 405; формы кабинета и его события должны обрабатываться по собственным маршрутам. PHP закрывает сессию после сборки страницы. Отображение ошибок отключено, ошибки направляются в журнал PHP. У текущей ревизии LOTIS на PHP 8.5 есть предупреждение о непубличном `Logger::__wakeup`; оно относится к исходнику фреймворка, в HTML не выводится и не мешает проверенной сборке лендинга. При обновлении LOTIS проверьте его отдельно.

## Цветовые варианты второго дизайна

`index.php?version=rocket-mint` — сайт в палитре логотипа. `index.php?version=rocket-orange` — логотип в оранжевой палитре сайта. Обе страницы используют общие сценарии кабинета и фиксированную таблицу шаблонов; стили палитр находятся в `palette-variants.css`.
